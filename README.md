# Свой дом: от простого к сложному

Публичная методичка самостоятельного проектирования и строительства дома с помощью ИИ-агентов — от участка до приёмки каждого этапа, с проверяемыми расчётами.

📖 **Начать отсюда:** [история проекта](<docs/история.md>) — как «просто баня» выросла в гостевой дом и эту методичку.

> **Статус:** черновик-оглавление.
> **Ограничение проекта:** в репозитории нет личных данных (координат, кадастровых номеров, выписок) — только методика и шаблоны. Личное остаётся в приватном проекте «стройка».

## Почему этот репозиторий существует

Я не строитель. Я проектирую дом на своём участке вместе с ИИ-агентом: модель участка в FreeCAD собирается скриптом, проверки считаются кодом, каждая сессия фиксируется в журнале и трекере задач. Началось всё с «просто бани» — а выросло в гостевой дом, методологию и этот репозиторий. Полная история — в [docs/история.md](<docs/история.md>).

По ходу проекта я увидел главный разрыв: знания о частной стройке разбросаны по видео, форумам и платным PDF технадзоров. Единой методички «от участка до акта приёмки», которую можно читать как код — с версиями, скриптами-проверками и честными ошибками, — не существовало. Теперь она здесь, и я пишу её по ходу собственной стройки.

## Окружение и роли

- **ИИ-агент** — opencode (open-source CLI), модель **GLM 5.3 Flash**. Это не Claude Code и не GPT — агент собран на связке opencode + MCP под свою методологию.
- **FreeCAD** подключён через MCP-сервер (freecad-mcp): агент собирает и правит модель кодом и сам запускает проверки.
- **Окружение я установил сам** — FreeCAD, MCP-агент, конфигурация. Всё работает локально.
- **Моя роль** — не рисовать и не считать. Отвечать агенту **честно** (размеры, факты, решения — врать бессмысленно, обманешь сам себя), проверять результат (скриншоты + контрольный вывод скриптов) и корректировать. Цикл: вопрос → честный ответ → сборка → автопроверка → моя приёмка → правка.

Поэтому это методичка не «как я заставил ИИ нарисовать домик», а «как человек с ИИ-агентом доходят до проверяемого результата».

## Как читать

- Этапы идут по порядку [оглавления](#оглавление) — от документов к приёмке.
- В каждом этапе: **«Как это было у меня»** (повествование с ошибками) → метод по шагам → нормативная рамка → скрипты → чек-лист → типичные ошибки.
- Скрипты запускаются на синтетических примерах «из коробки» — крути под себя.
- Личные данные в репозиторий не попадают — методика отделена от фактуры.
- Нормативная база собрана в одном месте: [docs/нормативная-документация.md](<docs/нормативная-документация.md>) — с датой актуальности каждой записи.
- Разрешительные документы — отдельный подраздел: [docs/разрешительная-документация/](<docs/разрешительная-документация/README.md>) — ПЗЗ, ГПЗУ, уведомления, техприсоединение, регистрация.

## Формат каждого этапа

Единая структура разделов:

**Цель → Исходные данные → Что проверить → Нормативка (СП/ГрК) → Расчёт (скрипт) → Чек-лист приёмки → Типичные ошибки → Шаблон акта**

## Структура репозитория

```
├── docs/        # этапы методички
├── templates/   # чек-листы и акты приёмки
└── scripts/     # расчётные скрипты (координаты, отступы, сборка модели)
```

## Как ведётся работа

- Методика переносится из приватного проекта «стройка» в обезличенном виде.
- Оглавление — чек-лист: этап коммитится по мере готовности раздела.
